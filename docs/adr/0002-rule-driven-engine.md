# ADR-0002 · 规则驱动，而非代码硬编码

- 状态：已采纳
- 日期：2026-10-26

## 背景

需求首期只覆盖哔哩哔哩，但明确要求「以后可能接入抖音」，且用户在真机上无法自行改代码。

## 决策

**不在代码里出现任何应用名判断**。所有应用差异表达为规则 JSON：

```
match   → 这条规则管谁
extract → 从事件里抠出哪些变量
targets → 按什么顺序、用什么方式跳转
```

引擎只实现「匹配 / 提取 / 降级链」三个通用动作。

## 理由

1. 新增应用 = 加一条 JSON（可通过设置页导入），**不需要发新版本**。
2. 规则可以互相分享（纯文本）。
3. 规则可以用 JUnit 直接测，不需要手机。
4. 万一某个规则写错，用户自己就能改回来，不必等作者。

## 代价

- 需要一套 JSON schema 与解析器（约 200 行）。
- 正则提取比硬编码字段读取慢一点点（可忽略，纯内存操作）。
- 规则出错时报错信息必须足够清楚（否则用户看不懂为什么没生效）。

## 后果

- `docs/RULES.md` 成为对外契约文档。
- 设置页必须提供「从命中日志一键生成规则」，降低编写成本。
